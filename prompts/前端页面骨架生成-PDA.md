## 与后台提示词的差异（改写说明）

原提示词面向销售订单 **B 端后台**（ProLayout + ProTable）。PDA 三页是 **375px 竖屏作业流**，必须改掉下列默认：

| 原提示词 | PDA 改写 |
| :--- | :--- |
| 销售订单列表 / 新增 / 详情 | 分货作业页、上架（入口+作业+明细）、装车（计划列表+扫描装车） |
| 左侧菜单 + 顶部导航作为页面骨架 | 作业页自身：顶栏 → 扫描/信息区 → 卡片列表 → 底部固定栏；桌面预览用 **375px 容器**，不把作业区做成宽表 |
| 列表优先 ProTable | **禁止**用 ProTable / 桌面宽表承载扫描作业；用 `MobileListCard` |
| ProComponents 默认范式优先 | 只借用 antd 组件实现 Demo 控件语义；冲突时 **Demo PRD 优先** |
| 菜单：销售管理 → 销售订单 | `PDA → 入库管理 → 分货/上架`；`PDA → 出库管理 → 装车`；上架另有 `库内作业 → 移库作业 → 上架 TAB` |

## 提示词

```text
你现在是一个熟悉仓储 PDA 作业、React、TypeScript、Ant Design v5 的前端产品设计助手。

我要基于已有《加盟揽收仓 PDA 主 PRD》、字段清单和 PDA Demo PRD，生成一组 **移动端** 作业页面原型：分货、上架、装车。

请基于 React 技术栈实现。视觉承载使用 Ant Design v5 默认组件，不要从零自定义视觉风格，也不要改用 Vue、原生 HTML、纯静态页或 antd-mobile（避免两套视觉）。

实现要求：
1. 技术栈：React 函数组件 + TypeScript + Ant Design v5。项目已有 `@ant-design/pro-components` 时，**仅允许**复用现有应用壳（如 ProLayout）做桌面预览外框；**作业页内部禁止** ProTable、ProForm、桌面查询区 + 宽表格骨架。
2. 前端 Demo PRD 是页面结构、控件类型、交互行为、校验反馈文案、空/加载/错误态的最高优先级来源：
   - 分货 → `04-05-分货_Demo.md`
   - 上架 → `04-06-上架_Demo.md`（一个文件内多子页，不拆成后台三页）
   - 装车 → `04-07-装车_Demo.md`（含简化的装车计划列表 + 作业页）
3. 主 PRD 和字段清单是业务字段、状态、操作、枚举、计算口径的最高优先级来源；Demo PRD 只翻译呈现，不发明规则。
4. Ant Design 只负责承载 Demo PRD 的页面规则，不能反过来用后台表单/表格范式覆盖 Demo PRD。
5. 作业页必须按 **PDA 移动端外壳** 展示，而不是管理后台内容区：
   - 设计基准宽度 **375px** 竖屏；内容区纵向滚动；底部主操作不随列表滚走
   - 骨架：顶栏 →（扫描区）→ 白底信息区 → 灰底卡片列表 → `FixedBottomBar`
   - 在桌面浏览器预览时：内容区居中放置 375px 作业容器；不要让页面铺满宽屏表格
   - 如项目已有 Layout / Menu / Route，优先复用；为 PDA 增加独立菜单与路由，不要挂到「订单管理」后台菜单下冒充列表页
6. 菜单和路由以 Demo PRD 为准：
   - 分货：`PDA → 入库管理 → 分货`，路径 `/pda/inbound/sorting`（不沿用现网绑托页）
   - 上架：`PDA → 入库管理 → 上架`，路径 `/pda/inbound/putaway`；作业页 `/pda/inbound/putaway/{作业单号}`；明细 `/pda/inbound/putaway/{作业单号}/detail`
   - 上架双入口：`PDA → 库内作业 → 移库作业 → 上架 TAB` 查询**同一批**上架单
   - 装车：`PDA → 出库管理 → 装车`；作业页 `/pda/transfer/load/{调拨计划单号}`
7. 列表与查询：
   - 待办/已扫明细一律 `MobileListCard` 卡片，不用 ProTable
   - 上架入口页 **不提供**筛选项（Demo：字段清单无可筛选 PDA 列表字段）
   - 装车计划列表本期仅展示 **状态=待出库** 的空单调拨卡片（Demo 简化 spec）
8. Demo PRD 控件语义必须保留，可用 Ant Design 组合实现，但不得改变业务含义：
   - `ScanInput` → `Input`（支持扫枪回车 + 软键盘）；扫码后 **自动校验**，无搜索按钮
   - `ReadonlyText` → 只读文本，不可改成可编辑 Form.Item
   - `MobileListCard` → `Card` / `List` 卡片行
   - `FixedBottomBar` → 底部固定操作区；主按钮高度 ≥ 44px
   - `BottomSheet` + `SelectWithSearch` → `Drawer`（从底部弹出）+ 可搜索选择；上架库位仅备货库位（R10）
   - `LocationPicker` → 卡片右侧「库位 >」，点开上述 BottomSheet
9. 状态展示、按钮显隐、二次确认弹窗、Toast 文案必须以对应 Demo PRD 为准：
   - **不渲染 disabled 按钮**（不可用时不展示，不用灰色禁用态）
   - 状态变更只通过底部动作按钮 + 弹窗确认，不允许在表单里改状态字段
10. 页面视觉沿用 Ant Design 默认风格，不自行发明新的颜色、圆角、阴影。三页视觉对齐：顶栏、白底头信息、灰底卡片列表、底部双按钮。
11. 如 Ant Design 默认范式与 Demo PRD 冲突，以 Demo PRD 为准，并在输出中说明取舍。典型冲突：
    - antd 默认按钮高度 32px vs Demo ≥ 44px → 用 44px
    - antd 常用 disabled vs Demo 不渲染不可用按钮 → 隐藏
    - antd Modal 居中 vs 库位选择 BottomSheet → 底部 Drawer
    - ProTable 查询分页 vs PDA 扫描作业 → 不用 ProTable
12. 先使用 mock 数据，不接真实接口。Mock 覆盖各 Demo「Mock 数据规格」；箱号、运单号用虚构数据。

页面清单（不要生成销售订单，不要生成后台列表/新增/详情）：

A. 分货作业页（`04-05`）
   - 顶栏「分货」
   - 常驻 `ScanInput`（placeholder：请扫描箱号）
   - 运单信息区只读：运单号、预报箱数、已扫进度、状态；不展示预报/收货重量体积
   - 扫描进度：当前托号、当前量/剩余量
   - 箱明细卡片：箱号、托号；长按当前箱可从当前量剔除（仅待收货）
   - 底部：重置（有扫描数据时）、确认绑托（至少 1 箱）；主按钮文案保持「确认绑托」
   - 弹窗/Toast：无预报、件数差异、剩余 ≤5 箱检查、绑托成功

B. 上架（`04-06`，单文件多子页）
   - 子页 A 入口：扫描箱号进入 或 待上架任务卡片（作业单号、运单号、托号、件数、初始库位列保留但值为空、状态）
   - 子页 B 作业：头信息三行（运单号/作业单号、作业类型、已上架/未上架箱与托）；**不展示初始库位**；托卡片选库位；底部重置 + 确认上架（未选库位则不展示确认上架）
   - 子页 C 明细：TAB 全部 / 已上架 / 未上架；行字段托号、箱号、库位
   - 跨库位不一致弹窗文案按 Demo B.6

C. 装车（`04-07`）
   - 计划列表（简化）：待出库空单卡片 → 进入作业页
   - 作业页：调拨头信息（单号、调出/调入仓库、状态；不展示调拨类型）→ 扫描区（请扫描箱号装车）→ 已扫运单卡片 → 汇总箱数/重量/体积 → 底部重置 + 装车
   - 不展示打印、取消、改仓库
   - 已出库/已完成/已取消：只读，无扫描区、无底部栏
   - 装车二次确认与拆票拦截文案按 Demo

输出目录：`front-prototype/`（复用现有工程）。完成后输出：
- 新增或修改的页面文件
- 应用外壳、菜单和路由入口的处理方式（含 375px 预览容器如何挂到现有壳上）
- 每个页面使用了哪些 Ant Design 组件（以及是否动用了 ProLayout 仅作外框）
- Demo PRD 中的关键规则分别落到了哪些页面和组件里
- 哪些地方直接沿用了 Ant Design 默认规范
- 哪些地方因为 Demo PRD 优先，没有采用 Ant Design 默认范式
- 哪些业务信息需要我人工确认（至少列出 Demo 已标注的待确认项：上架托级 vs 单级目标库位、大票多托头部托号取值）
```
