## 第一次会议

本次会议主要围绕揽收仓的业务需求展开，讨论了从加盟商下单、贴标、发货到揽收仓收货、分货、装车、调拨至东莞仓的完整流程，明确了系统对接方式（速达系统、加盟商系统与WMS的集成）、操作规范（如PDA扫描、托盘分货）、费用结算逻辑以及前期过渡方案（纸质流程）和培训计划。
1. 揽收仓整体流程设计
加盟商下单与贴标：加盟商收到客户货物后，需在加盟商系统（基于速达客户端开发）中录入运单信息并打印标签贴于箱上，完成运单预报。
货物流转至揽收仓：加盟商在系统中操作“发车”或“提交”功能，将货物发往指定的揽收仓（如南昌、赣州），系统自动将数据推送至WMS，揽收仓据此具备收货条件。
揽收仓收货与分货：揽收仓使用PDA扫描每箱货物，按运单号集中放置于托盘上，并上架至对应目的仓（如东莞）的备货区域。
调拨与装车：揽收仓完成收货后，由总部作业部创建调拨单（空单），扫描每票货关联至该调拨单，装车时打印装车清单并发车至东莞仓。
东莞仓接收：东莞仓收到货物后清点卸车，点“接收”完成揽收仓功能，后续进入常规操作流程。
2. 系统对接与数据流
加盟商系统与速达的关系：加盟商系统是速达客户端的独立版本，但底层数据库与速达共用，因此对仓库而言数据来源统一为速达。
数据推送到WMS的时机：加盟商在系统中点“发车”或“提交”后，数据即推送至WMS，WMS才能进行揽收仓的收货操作。
调拨单的创建方：调拨单由总部作业部统一创建（如按周创建），揽收仓在系统中可见，负责装车扫描即可，无需自行创建。
轨迹与信息流：加盟商点“发车”后，系统自动匹配下一站（揽收仓），揽收仓收货后点“接收”，再通过调拨单发车至东莞，轨迹完整串联。
3. 揽收仓具体操作规范
PDA扫描收货：揽收仓需使用PDA逐箱扫描，确保每票货集中放置，并自动生成托号，实现简单仓储管理。
分货逻辑：PDA支持分货功能，按托盘分配运单。例如，10票货对应10个托盘，扫描第一箱时提示放1号托盘，第二箱放2号托盘，直至托盘满后点“确定”换新托盘。小票可多票共托（最多5票），大票需一票一托或多托。
托盘要求：揽收仓必须配备托盘（周转托盘），用于分货和叉车搬运，数量根据货量而定（50-300个）。
装车操作：装车时，若货物有托盘，只需扫描一个箱号即可整托装车；若无托盘，需逐票扫描。装车后点「发车」，调拨单自动完成并通知东莞仓。**（第一次会议口述，已与定稿冲突；以第二次会议 §四、文头口径说明及《03-01》§3.4 为准：PDA「装车暂存/装车锁定」回写实装并占用箱库存；装车锁定或 PC 手动锁单后出库单→已复核；PC 须先打印装柜单再确认出库→已出库；调拨→已完成由东莞对该计划全部关联运单常规入库收货完成回写，非装车即完结。）**
操作人员配置：按此流程，收货约需3-4人，发货同时装两台车约需6人，总计10人左右，可减少对大量装卸工的依赖。
4. 费用结算与统计
费用归属：揽收仓的运输费用由加盟商自行承担，公司不记录在系统内，前端已通过底价加价方式收取。
结算依据：公司与加盟商按揽收仓操作吨位结算，以东莞仓入库测量的重量为准（如100kg或200kg），由前端与加盟商手动结算。
数据统计需求：刘宏(Lyho Liu@德速电商物流)的仓库系统需统计每天从南昌、赣州等地发往东莞的货量，供屈甜(Tiana Qu@德速电商物流)用于与加盟商结算。
5. 前期过渡方案与培训计划
纸质流程：在系统上线前（预计9月底），采用Excel表格和纸质清单进行交接。揽收仓需按清单清点货物，将同票货集中放托盘，并生成装车单。
系统上线时间：系统预计9月20日左右完成，届时可实现无纸化操作。
培训安排：9月初需安排人员前往南昌和赣州进行现场培训，指导加盟商和揽收仓操作人员使用系统及纸质流程。
其他省份加盟商模式：对于无揽收仓的省份（如湖北仅两人），加盟商可直接使用客户端点“发车”，将货物直发东莞仓，无需经过揽收仓。

## 第二次会议（2026-09-05）

> **会议主题**：速达加盟商新增发车功能后的揽收仓全流程确认与调整  
> **主链路**：发车 → 预报 → 收货 → 分货 → 上架 → 装车 → 打印装柜单 → PC 确认出库  
> **口径说明**：本节与第一次会议冲突时，以本节为准；上架库位统一称「备货库位」。

### 一、整体流程

1. 加盟商在客户端点「发车」→ 订单推送 WS，预报至揽收仓（按客户代码配置，**一加盟商一揽收仓**）
2. 揽收仓：收货 → PDA 分货绑托 → 上架 → OMS 创建空调拨单 → 装车
3. **装车锁定后**，PC 端须**先打印装柜单**，现场确认无误后**再点击确认出库**（调拨单可能未装完，需最终确认收口）

**PDA 故障兜底**：PC 端「关联运单」建立关联 → **手动锁单**（现网功能）→ **打印装柜单** → 现场确认 → **确认出库**

### 二、分货（PDA）

- 进入时弹窗设置托数：**1~99，默认 5**
- **大票**：按托扫描，托满点「托满」绑托
- **小票**：可混托（后台配置上限 **P**，如 5 票），须扫齐该托所有箱才能托满
- 支持**多 PDA 并行**，各管自己的托；单台完成才能提交，**全部绑完才能上架**
- **全仓可用**（不限加盟揽收仓），少件处理本期不做

### 三、上架（PDA）

- 分货完成后生成上架单，作业方式类似移库：先扫描再带出单
- 上架至**备货库位**，**一托一上架**（一托多运单整托一起上）

| 仓库类型 | 上架前提 |
| -------- | -------- |
| 加盟揽收仓 | **不测量可上架** |
| 非加盟揽收仓 | **须测量完成后才能上架** |

### 四、出库（装车 + 确认）

**调拨单**：OMS 创建空单，选择调出仓（揽收仓）+ 调入仓（**本期仅东莞**）；**建计划时同步生成空出库单**（**待出库**、明细空，1 计划 : 1 出库单）

**PDA 装车**：

- 扫一箱带出整托；混托扫一箱带出整托所有运单（分货时同托运单目的仓须一致）
- 按运单顺序装车，**不可拆票**，须整票所有托装完才能扫下一票
- **「装车暂存」**：部分装车后保存进度，不锁定单据；将已扫运单**关联至空出库单**并回写调拨明细（出库单**仍为待出库**）；提交前须校验**可用库存**，不足则不可提交；保存后将关联**箱库存**更新为**已占用**
- **「装车锁定」**：确认装车完成并锁定；提交前须校验**可用库存**，不足则不可提交；保存后将关联**箱库存**更新为**已占用**；**出库单→已复核**、调拨计划→**已复核**；锁定后要继续装车，须到 **PC 端解锁**
- 点「装车锁定」时提示：锁定后需到 PC 端解锁

**PC 端**（本期新增）：

- **「关联运单」**：PDA 无法扫描时，手动输入/勾选运单，**仅建立运单与出库单的关联关系，不变更出库单/调拨单状态**；**待出库或已复核**可进入/展示入口，**已出库或已锁单**不显示；提交前须校验**当前仓库**可用库存（**箱库存=已占用**或**查不到该仓库存**均不可用），不足则不可提交；保存后将关联**箱库存**更新为**已占用**；须再到调拨详情**手动锁单**

**锁单逻辑**：

- PDA：点「装车锁定」后锁单（单据锁定）
- PC：关联运单后，须**手动操作锁单**（沿用现网功能，单据锁定）

**库存占用**：装车暂存、关联运单、装车锁定三类操作保存时均占用箱库存；区别在单据是否锁定（暂存/关联不锁单，装车锁定/手动锁单锁单）

**发运收口（PC）**：装车锁定/手动锁单后，须**先打印装柜单**（沿用现网模板），现场确认无误后**再点击确认出库**

**范围**：本期先做揽收仓调拨；全仓调拨及费用计算后续讨论

### 五、其他确认

- **目的仓控制**：客户端下单时按角色限制可选目的仓，**当前加盟商仅能选东莞**；后续按加盟商开放
- **分货通用化**：外包商、东莞仓等均可使用 PDA 分货

- 全仓调拨及费用计算
