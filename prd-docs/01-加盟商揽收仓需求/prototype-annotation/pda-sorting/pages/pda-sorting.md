## 需求描述：【分货绑托页】

> 来源：03-02 §十二、§6.1（R33/R37–R47）；04-05 分货 Demo §3–§8

### 页面入口

- PDA → **入库管理 → 分货**
- 路径 `/pda/inbound/sorting`

### 改动逻辑

1. **票型规则**：预报箱数 ≤ **M** 为小票，> **M** 为大票（R37）；**M/P** 由后台按加盟揽收仓配置，未配置则阻断（R48）。
2. **数据范围**：运单状态须为**待收货、已收货或收货中**；**已绑托箱号**不可重复扫描。
2. **绑托原则**：无系统满托容量；操作员判断托满后点「托满」（R40）；**不存在部分绑托状态**；全部箱绑完→**已绑托**并生成上架单（R33/R43）；绑托阶段**无库存变动**。
3. **小票逻辑**：同票同托；多票可混一托（≤P）；须扫齐全箱方可绑托（R45）；混托托满生成**一张**上架单含全部运单。
4. **大票逻辑**：同托同票不可混托（R38）；可拆多托、允许部分箱绑托；全部箱绑完才已绑托并生成上架单。
5. **作业托数 N**：进入先弹窗确认 N（1–99，默认 5），不可跳过（R41）；N=1 单托单分，N>1 多托同分；写入 sessionStorage。
6. **进入托 N 强化**：落托确认弹窗大号展示目标托号；目标托卡片主色边框/浅底、左侧色条高亮。

### 页面分区

| 分区 | 要点 |
| --- | --- |
| 作业托数弹窗 | 确认 N 后预生成 N 个托位；顶栏只读展示 `作业托数 N` |
| 扫描区 | `ScanInput` 置顶；扫码自动校验；失败 Toast 见 Demo §4.1；成功后弹出落托确认 |
| 落托确认弹窗 | 标题「落托确认」；展示箱号、运单号；**大号高亮目标托号**；扫描键等同确认（R46） |
| 托列表 | N 个托卡片；嵌套箱明细；当前/目标托**明显高亮**（边框、背景、色条）；每格「托满」触发确认绑托 |
| 绑托反馈 | 小票未扫齐→「小票须扫齐全部箱方可绑托」；件数不一致→协调上游弹窗；成功 Toast「绑托成功」 |

- 可扫描箱号见补充标注 **A1**；不提供长按剔除、过机顺序、暂存等现网能力（§12.5）。

## 需求描述：【原型 Mock · 可扫描箱号】

> 来源：04-05-分货_Demo.md §11；`front-prototype/src/mocks/pda-sorting.ts`

### 可扫描箱号（扫描成功）

箱号格式：`FBA1988W5Y0GU` + 6 位流水（如 `FBA1988W5Y0GU000001`）。

| 运单号 | 场景 | 可扫箱号（示例） | 箱数 |
| --- | --- | --- | --- |
| DSL26010128343 | 大票多托 | `000001`～`000350` | 350 |
| DSL26010128301 | 大票一票一托 | `000351`～`000380` | 30 |
| DSL26010128302 | 小票混托 A | `000381`～`000388` | 8 |
| DSL26010128303 | 小票混托 B | `000389`～`000393` | 5 |
| DSL26010128304 | 小票混托 C | `000394`～`000399` | 6 |

- 扫任一箱号即带出对应运单；同运单可继续扫该运单下其余箱号。

### 拦截用箱号（不可扫入成功）

| 箱号 | 触发 |
| --- | --- |
| `FBA1988W5Y0GU888888` | 无预报箱号（S08） |
| `FBA1988W5Y0GU000400` | 该箱已绑托，不可重复扫描（运单 DSL26010128399） |
| 其他未列入索引的箱号 | 箱号不存在 |

### 研发备注

- 与上架 Mock（`putaway.ts`）箱号段对齐：DSL26010128343 使用 `000001` 起。
