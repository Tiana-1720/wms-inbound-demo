## 需求描述：【作业托数弹窗】

> 来源：04-05-分货_Demo.md §3；03-02-加盟商揽收仓PDA主PRD.md §十二（R41）

### 业务定义

- 进入分货页**先展示弹窗**，用户确认作业托数 N 后进入主界面；**不可跳过**（无取消、不可点遮罩关闭）。
- **N=1** 单托单分；**N>1** 多托同分（小票首箱入混托格）。
- N 写入 `sessionStorage`，退出应用前保持。
- **M/P 未配置**：进入时 Toast「请先配置分货参数」，阻断作业（R48）。

### 字段与状态

| 字段 | 必填/可编辑 | 核心约束 |
| --- | --- | --- |
| 作业托数 N | 必填 | 默认 1；范围 1–10；`InputNumber` |

### 交互规则

- 确认「开始作业」后关闭弹窗，预生成 N 个托位。
- 主界面顶栏下只读展示 `作业托数 N`（作业中不可修改）。

### 研发备注

- 挂载点：`[data-anno='pda-sorting-setup-modal']`（弹窗可见时校验）。

## 需求描述：【扫描区与校验】

> 来源：04-05-分货_Demo.md §4、§4.1；03-02-加盟商揽收仓PDA主PRD.md §5.1.3、§6.1、§12.2–§12.3

### 业务定义

- `ScanInput` 置顶常驻；placeholder：`请扫描箱号`；扫码后**自动校验**，无需点搜索。
- **不校验**收货订单**状态**、**预报仓库**/**收货仓库**（R02/§12.3）。

### 交互规则

| 校验项 | 失败反馈 |
| --- | --- |
| 箱号/运单不存在 | Toast：`箱号不存在` |
| 箱号无预报（S08） | Toast：`无预报箱号，不可分货` |
| 箱号已绑托 | Toast：`该箱已绑托，不可重复扫描` |
| 大票扫入含其他运单的格 | Toast：`大票不可混托` |
| 小票须落原格却扫入他格 | Toast：`小票须在同一托` |
| 混托格已达 P 票上限 | Toast：`混托票数已达上限` |
| N 格占满且须绑托释放 | Toast：`请先确认绑托释放托` |

- 扫描成功后弹出**落托确认**（见标注 5），关闭后当前箱高亮，累加对应托「已扫箱数」。
- **重置扫描**：已有扫描数据时，扫描区下方链接展示；清空本页未提交缓存。

### 研发备注

- 挂载点：`[data-anno='pda-sorting-scan']`。
- 可扫描箱号清单见补充标注 **A1**。

## 需求描述：【原型 Mock · 可扫描箱号】

> 来源：04-05-分货_Demo.md §12；`front-prototype/src/mocks/pda-sorting.ts`

### 可扫描箱号（扫描成功）

箱号格式：`FBA1988W5Y0GU` + 6 位流水（如 `FBA1988W5Y0GU000001`）。

| 运单号 | 场景 | 可扫箱号（示例） | 箱数 |
| --- | --- | --- | --- |
| DSL26010128343 | 大票多托 | `000001`～`000350` | 350 |
| DSL26010128301 | 大票一票一托 | `000351`～`000380` | 30 |
| DSL26010128302 | 小票混托 A | `000381`～`000388` | 8 |
| DSL26010128303 | 小票混托 B | `000389`～`000393` | 5 |
| DSL26010128304 | 小票混托 C | `000394`～`000399` | 6 |

- 扫任一箱号即带出对应运单；同运单可继续扫该运单下其余箱号。

### 拦截用箱号（不可扫入成功）

| 箱号 | 触发 |
| --- | --- |
| `FBA1988W5Y0GU888888` | 无预报箱号（S08） |
| `FBA1988W5Y0GU000400` | 该箱已绑托（运单 DSL26010128399） |
| 其他未列入索引的箱号 | 箱号不存在 |

### 研发备注

- 与上架 Mock（`putaway.ts`）箱号段对齐：DSL26010128343 使用 `000001` 起。

## 需求描述：【运单信息区】

> 来源：04-05-分货_Demo.md §6；02-01-收货订单-入库单字段清单.md §一、§二

### 业务定义

- 白底信息块，展示**当前扫描运单**（最近一次成功扫码所属运单），字段均 **ReadonlyText**（R31）。
- **状态**仅作展示，**不作为扫描拦截条件**。

### 字段与状态

| 字段 | 展示格式 | 核心约束 |
| --- | --- | --- |
| 运单号 | `运单号：DSL…` | 只读 |
| 预报箱数、扫描进度 | `预报：350箱`　`已扫：12箱`　`可扫：338箱` | 已扫=该运单当前会话累计，绑托前未回写**收货箱数** |
| 可扫描箱数 | 系统计算（呈现层） | `可扫 = 预报箱数 − 已扫箱数`；最小为 0；随每次成功扫码实时刷新 |
| 状态 | Tag | 只读展示 |
| 大小票 | Tag | 预报箱数 ≤ **M** 为小票，> **M** 为大票 |

**不展示**：预报重量、预报体积、收货重量、收货体积（R05）。

### 研发备注

- 未扫描时占位文案：`扫描箱号后展示运单信息`。
- 挂载点：`[data-anno='pda-sorting-waybill']`。

## 需求描述：【托列表与确认绑托】

> 来源：04-05-分货_Demo.md §7、§8、§9；03-02-加盟商揽收仓PDA主PRD.md §十二（R40/R45/R47）

### 业务定义

- 展示 **N** 个托卡片；每卡展示**托序号**（托 1 … 托 N），**不展示托号**。
- 混托格展示每票 `已扫/预报` 箱数，并隐含剩余可扫 `预报 − 已扫`，未扫齐标红。
- 点击格切换当前操作格；扫码落入规则由 §12.3/R47 决定。
- **不提供**长按剔除、过机顺序带出、暂存等现网绑托页能力（§12.5）。

### 交互规则

- 每格底部「托满」：至少扫入 1 箱时展示；触发**确认绑托**。
- **托号生成时机**：点击「托满」且校验通过后，系统生成**唯一托号**（如 `PL25010100001` 递增）；绑托前页面不展示托号。
- 格内含**小票**：每一票须 `已扫箱数 = 预报箱数`，否则 Toast：`小票须扫齐全部箱方可绑托`。
- 格内仅**大票**：允许部分箱绑托。
- 件数与预报箱数不一致（绑托提交时）：弹窗 `实收与预报不一致，请协调上游取消后重发`。
- 绑托成功 Toast：`绑托成功`；**小票混托**时追加提示 `已生成上架单 TK…`（`putaway-sync.ts`）。
- **同事务生成上架单**（R33）：混托格→一张含多运单；独托→运单全部箱绑托完成后一张。

### 研发备注

- **不展示**固定底部「确认绑托」栏；绑托收敛至各格「托满」。
- 挂载点：`[data-anno='pda-sorting-pallets']`。
