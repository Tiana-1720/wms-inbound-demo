## 需求描述：【装车作业页】

> 来源：04-07 装车 Demo §1–§6；03-02 §十三；02-02 调拨计划单字段清单

### 页面入口

- PDA → 出库管理 → 装车 → 点击待出库计划卡片
- 路径 `/pda/transfer/load/{调拨计划单号}`

### 改动逻辑

1. **适用范围**：仅**空单调拨**（调出仓=加盟揽收仓）；扫描已上架库位库存装车。
2. **会话保持**：进入本页带出该计划未提交已扫票/托；新扫描运单插入明细**顶部**（混托多票作为一组排最前）。
3. **扫描进度**：每票展示 **已扫箱数/运单总箱数**；扫 1 次带出托上全部运单；按已扫托累加**本托箱数**（混托同扫各票满进度，多托分次累加）。
4. **装车暂存**：校验可用库存；保存进度；**不锁单据**；出库单仍为待出库；箱库存→已占用；Toast「暂存成功，已占用库存」。
5. **装车锁定**：打开司机信息弹窗；填写司机/电话/车牌必填；确认后出库单→**已复核**、调拨计划→**已复核**；箱库存→已占用；Toast「装车锁定成功，已占用库存」。
6. **只读阻断**：调拨已出库、出库单已出库或**是否锁单=是**→整页只读，无扫描区与底部栏（R32）。

### 页面分区

| 分区 | 要点 |
| --- | --- |
| 调拨头信息 | 计划单号；调出/调入仓库；`已扫：N票 / M托` 实时更新 |
| 扫描区 | `ScanInput` 扫箱号；整票/整托关联；不允许拆票；规则与 Mock 见 **A1** |
| 装车明细 | 已扫运单列表；每票 **已扫箱数/运单总箱数**；卡片「移除」按整托删除（混托多票一并移除） |
| 底部操作 | **装车锁定**（左，次要）/ **装车暂存**（右，主色）；有明细且未出库时展示；不展示重置/打印 |
| 司机信息弹窗 | 司机、电话、车牌号必填；确认后直接触发装车锁定 |

### 空单调拨·出库下推（本页）

| 阶段 | 系统行为 |
| --- | --- |
| PDA 装车暂存 | 关联运单至出库单；仍为待出库；箱库存→已占用 |
| PDA 装车锁定（本页） | 出库单→已复核；调拨计划→已复核；箱库存→已占用 |
| PC 确认出库 | 出库单→已出库；库位库存实扣 |
| 调入仓入库 | 不生调拨入库单；东莞常规入库由发车现网推送 |

### 研发备注

- 挂载点：`[data-anno='pda-load-work-page']`。
- 原型会话：`sessionStorage` 键 `wms-prototype-load-session:{调拨计划单号}`；装车锁定成功清空会话。

## 需求描述：【装车计划列表】

> 来源：04-07 装车 Demo §2.2；03-02 §十三、§7.1

### 页面入口

- PDA → **出库管理 → 装车**
- 路径 `/pda/transfer/load`

### 改动逻辑

1. **数据范围**：查询关联出库单**状态=待出库或已复核**且**是否锁单=否**的空单调拨（调出仓命中本仓）；**已出库**或**已锁单**不展示；计划调拨不展示（R19）。
2. **可见性**：调出仓库或调入仓库命中本仓可见。
3. **进入作业**：点击卡片进入作业页，**恢复该计划未提交已扫明细**；列表 `已扫` 与作业页实时一致。

### 页面分区

| 分区 | 要点 |
| --- | --- |
| 计划卡片 | 主行：调拨计划单号（加粗）；副行：调出/调入仓库；进度 `已扫：N票 / M托` |
| 空态 | `暂无可装车调拨计划` |

**不展示**：状态 Tag、出库单状态 Tag、汇总箱数。

### 研发备注

- 挂载点：`[data-anno='pda-load-list-page']`。
- 作业页规则见同模块标注 **0**；扫描 Mock 见 **A1**。

## 需求描述：【扫描区 · 原型 Mock 可扫描箱号】

> 来源：04-07-装车_Demo.md §3、§3.1、§8；03-02-加盟商揽收仓PDA主PRD.md §5.2.3、§6.4（R31）；`front-prototype/src/mocks/pda-transfer-load.ts`

### 业务定义

- `ScanInput` placeholder：`请扫描箱号装车`；扫码**自动校验**。
- 扫箱号**带出整托**入明细（Q12）。绑托时**多票可混一托**，装车扫任一箱即关联**该托上全部运单**（顶部 `已扫：票/托` 分别计数）。
- 明细每票展示 **已扫箱数/运单总箱数**：按已扫托累加**本托箱数**；混托同扫各票满进度（如各 **10/10**）；多托分次累加（如先 **10/20**）。
- **多托扫描顺序**（仅原型标注 · R31）：同一运单在库位库存中若对应多托，须扫齐该运单全部托后，才能扫描下一运单的托。未扫齐时扫其他运单 → Toast：`请先扫齐当前运单全部托`。
- 新扫描入明细**插入列表顶部**（后扫的托/票排在最前；混托多票作为连续一组置顶）。
- 进入作业页**带出该计划单号未提交的已扫票/托**（列表与头信息 `已扫` 同步恢复）。
- **不允许拆票装车**（Q15）：卡片「**移除**」按整托删除已扫运单（混托多票一并移除，`03-02` R56）。

| 规则 | 失败反馈 |
| --- | --- |
| 货物须在库位库存且已上架（R20、S10） | Toast：`货物未上架或不在库` |
| 每扫 1 次校验**当前托下全部箱**可用库存；任一箱被占用 | Toast：`箱号{箱号}已被{占用方}占用`（占用方如其他调拨计划单号） |
| 重复扫描同一托 | Toast：`该运单已关联` |
| 运单多托未扫齐扫下一票（R31） | Toast：`请先扫齐当前运单全部托` |

箱号格式：`FBA1988W5Y0GU` + 6 位流水。

Mock 多托示例：`DSL26010128343` 总 **20 箱**、共 **2 托**（各托 10 箱；`PL25010100001` / `000001` + `PL25010100005` / `000002`）。

| PL25010100020 | DSL26010128303 | `FBA1988W5Y0GU000389` | ✅ 同上（同托任一扫即可） |

**推荐验证路径**：

| 场景 | 操作 |
| --- | --- |
| 单票单托 | 扫 `FBA1988W5Y0GU000001` → 明细 1 票，进度 **10/20**，顶部 `已扫：1票 / 1托` |
| 单票多托 | 扫 `000001` 后扫 `000401`（另一运单）→ Toast `请先扫齐当前运单全部托`；补扫 `000002` 后进度 **20/20**，再扫 `000401` → 通过 |
| 小票混托 | 扫 `FBA1988W5Y0GU000381` → 明细 3 票（28302/28303/28304），各票满进度，顶部 `已扫：3票 / 1托` |
| 会话保持 | 扫 `000001` 后返回列表 → 卡片 `已扫：1票 / 1托` → 再进作业页明细仍在 |
| 新扫置顶 | 在已有 `000001` 基础上再扫 `000401` → `DSL26010128344` 出现在明细**最上方**，`已扫：2票 / 2托` |
| 装车锁定后双已复核 | **装车锁定**成功 → 出库单/调拨**已复核**且**是否锁单=是**；**不再出现在装车列表** |

### 研发备注

- 挂载点：`[data-anno='pda-load-work-scan']`。
- 列表入口：`/pda/transfer/load` 展示出库单**待出库/已复核且未锁单**的空单调拨（如 AT26010100001、AT26010100003、AT26010100004）；**已锁单**（如 AT26010100005）不展示。
- 原型会话：`sessionStorage` 键 `wms-prototype-load-session:{调拨计划单号}`；**装车锁定**成功时清空会话（明细已写入计划单）；**装车暂存**保持会话。
- **装车锁定**成功后：**调拨计划与出库单均为已复核**，回写明细并**占用**箱库存（与标准需求一致）。
