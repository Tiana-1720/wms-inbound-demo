## 需求描述：【装车作业页总览】

> 来源：04-07-装车_Demo.md §1；03-02-加盟商揽收仓PDA主PRD.md §十三

### 业务定义

- 路径 `/pda/transfer/load/{调拨计划单号}`；仅**空单调拨**（调出仓=加盟揽收仓）。
- 扫描已上架库位库存装车；点「装车」按**空单调拨出库下推规则**处理（见下）。
- **进入本页须带出该计划单号已扫描的票/托明细**（未提交装车前会话保持）；**新扫描的运单插入明细列表顶部**（混托多票作为一组排在最前）。

### 空单调拨·出库下推规则（原型标准需求）

| 阶段 | 系统行为 |
| --- | --- |
| OMS 建计划 | **不预生成**待出库出库单；调拨计划待出库、明细空 |
| PDA 装车（本页） | 生成/追加出库单→**已复核**；回写实装明细；**占用**库位库存 |
| PC 确认出库 | 出库单→**已出库**；库位库存**实扣** |
| 调入仓入库 | **不生调拨入库单**；东莞常规入库由发车**现网推送** |

### 子模块标注

| 角标 | 模块 | 挂载点 |
| --- | --- | --- |
| 2 | 调拨头信息 | `pda-load-work-header` |
| 5 | 底部操作栏 | `pda-load-work-bottom` |
| 6 | 司机信息弹窗 | `pda-load-driver-modal`（弹窗打开时） |
| A1 | 扫描区 · Mock 可扫描箱号 | `pda-load-work-scan` |

### 研发备注

- 挂载点：`[data-anno='pda-load-work-page']`。

## 需求描述：【装车计划列表】

> 来源：04-07-装车_Demo.md §2.2；03-02-加盟商揽收仓PDA主PRD.md §十三、§7.1

### 业务定义

- 路径 `/pda/transfer/load`；菜单 `PDA → 出库管理 → 装车`。
- 仅展示**状态=待出库**且**调出仓库**命中本仓的**空单调拨**卡片；计划调拨不展开（R19）。
- 数据范围：**调出仓库**或**调入仓库**命中本仓可见。

### 字段与状态

| 卡片区域 | 字段 | 展示 |
| --- | --- | --- |
| 主行 | 调拨计划单号 | 加粗 |
| 副行 | 调出仓库 | `调出：…` |
| 副行 | 调入仓库 | `调入：…` |
| 进度 | 已扫票/托 | `已扫：N票 / M托`；未扫时为 `0票 / 0托` |

**不展示**：状态 Tag、出库单状态 Tag、汇总箱数（`合计：N箱`）。

### 交互规则

- 点击卡片进入 `/pda/transfer/load/{调拨计划单号}`；进入作业页后**恢复该计划未提交的已扫明细**。
- 列表卡片 `已扫` 与作业页头信息、明细**实时一致**（含退出再进入）。
- 空状态：`暂无可装车调拨计划`。

### 研发备注

- 挂载点：`[data-anno='pda-load-list-page']`。

## 需求描述：【扫描区 · 原型 Mock 可扫描箱号】

> 来源：04-07-装车_Demo.md §3、§3.1、§8；03-02-加盟商揽收仓PDA主PRD.md §5.2.3、§6.4（R31）；`front-prototype/src/mocks/pda-transfer-load.ts`

### 业务定义

- `ScanInput` placeholder：`请扫描箱号装车`；扫码**自动校验**。
- 扫箱号**带出整托**入明细（Q12）。绑托时**多票可混一托**，装车扫任一箱即关联**该托上全部运单**（顶部 `已扫：票/托` 分别计数）。
- **多托扫描顺序**（仅原型标注 · R31）：同一运单在库位库存中若对应多托，须扫齐该运单全部托后，才能扫描下一运单的托。未扫齐时扫其他运单 → Toast：`请先扫齐当前运单全部托`。
- 新扫描入明细**插入列表顶部**（后扫的托/票排在最前；混托多票作为连续一组置顶）。
- 进入作业页**带出该计划单号未提交的已扫票/托**（列表与头信息 `已扫` 同步恢复）。
- **不允许拆票装车**（Q15）：卡片「**移除**」按整托删除已扫运单（混托多票一并移除，R50）。

| 规则 | 失败反馈 |
| --- | --- |
| 货物须在库位库存且已上架（R20、S10） | Toast：`货物未上架或不在库` |
| 每扫 1 次校验**当前托下全部箱**可用库存；任一箱被占用 | Toast：`箱号{箱号}已被{占用方}占用`（占用方如其他调拨计划单号） |
| 重复扫描同一托 | Toast：`该运单已关联` |
| 运单多托未扫齐扫下一票（R31） | Toast：`请先扫齐当前运单全部托` |

箱号格式：`FBA1988W5Y0GU` + 6 位流水。

Mock 多托示例：`DSL26010128343` 共 **2 托**（`PL25010100001` / `000001` + `PL25010100005` / `000002`）。

### AT26010100001 / AT26010100003（待出库空单，调入 DS-JH-01）

| 托号 | 运单号 | 可扫箱号（任一扫） | 结果 |
| --- | --- | --- | --- |
| PL25010100001 | DSL26010128343 | `FBA1988W5Y0GU000001` | ✅ +1 票 / +1 托（30 箱）；**该运单共 2 托，须扫齐后再扫下一票** |
| PL25010100005 | DSL26010128343 | `FBA1988W5Y0GU000002` | ✅ 同上运单第 2 托；两托扫齐后 `DSL26010128343` 完成 |
| PL25010100002 | DSL26010128344 | `FBA1988W5Y0GU000401` | ✅ +1 票 / +1 托（30 箱） |
| PL25010100020 | DSL26010128302 | `FBA1988W5Y0GU000381` | ✅ **小票混托**：+3 票 / +1 托 |
| PL25010100020 | DSL26010128303 | `FBA1988W5Y0GU000389` | ✅ 同上（同托任一扫即可） |
| PL25010100020 | DSL26010128304 | `FBA1988W5Y0GU000394` | ✅ 同上（同托任一扫即可） |
| PL25010100021 | DSL26010128399 | `FBA1988W5Y0GU000701` | ❌ 托上 `000702` 已被 `AT26010100999` 占用 → Toast：`箱号FBA1988W5Y0GU000702已被AT26010100999占用` |
| PL25010100004 | DSL26010128346 | `FBA1988W5Y0GU000601` | ❌ 货物未上架或不在库 |

**推荐验证路径**：

| 场景 | 操作 |
| --- | --- |
| 单票单托 | 扫 `FBA1988W5Y0GU000001` → 明细 1 票，顶部 `已扫：1票 / 1托` |
| 单票多托 | 扫 `000001` 后扫 `000401`（另一运单）→ Toast `请先扫齐当前运单全部托`；补扫 `000002` 后再扫 `000401` → 通过 |
| 小票混托 | 扫 `FBA1988W5Y0GU000381` → 明细 3 票（28302/28303/28304），顶部 `已扫：3票 / 1托` |
| 会话保持 | 扫 `000001` 后返回列表 → 卡片 `已扫：1票 / 1托` → 再进作业页明细仍在 |
| 新扫置顶 | 在已有 `000001` 基础上再扫 `000401` → `DSL26010128344` 出现在明细**最上方**，`已扫：2票 / 2托` |
| 重复演示 | 装车确认成功后 Mock 清空会话并回滚，可重复扫上述箱号 |

### 其他

| 场景 | 说明 |
| --- | --- |
| 未登记箱号 | Toast：`箱号不存在` |
| 同托重复扫描 | Toast：`该运单已关联` |
| AT26010100002 | 已出库只读，无扫描区 |

## 需求描述：【底部操作栏与装车确认】

> 来源：04-07-装车_Demo.md §6、§6.1–§6.2；03-02-加盟商揽收仓PDA主PRD.md §5.2.4、§十三

### 交互规则

| 按钮 | 展示条件 | 行为 |
| --- | --- | --- |
| 装车 | 待出库且已有扫描明细 | 点击「装车」→ 打开弹窗输入司机信息（见标注 6）；点「确认装车」提交 |

**不展示**：重置、取消、修改调出/调入仓库、打印装车清单（Q17）。

- 点击「装车」→ 打开**司机信息弹窗**，输入司机、电话、车牌。
- 装车成功 Toast：`装车成功，已占用库存`；返回列表。

### 结果处理

- **PDA 装车**：生成/追加出库单→**已复核**；回写调拨明细；**占用**库位库存。
- **PC 确认出库**：出库单→**已出库**；库位库存**实扣**。
- **不生**调入仓**调拨入库单**（东莞常规入库由发车现网推送，R18/R26）。

> 原型 Mock：装车确认成功后回滚至初始快照，**不落库**出库单状态与占用，便于重复演示；上表为**标准需求**口径。

- Demo PRD §6 原写「司机/电话/车牌已填」才展示装车按钮；**原型已调整为**有明细即可点装车、弹窗内维护司机信息（Demo PRD §2.1 内联区已收起，**待确认**是否回写 Demo）。
